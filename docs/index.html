The problem

AI writes bugs. Every language ships them differently.

When you vibe code an ecommerce backend, the AI will eventually generate a function that sells more inventory than exists, sets a price to zero, or calculates the wrong total. What happens next depends on your language.

Python — ships the bug
python main.py
# AI wrote: sell 5 laptops (only 3 in stock)
product["stock"] -= quantity
# stock is now -2. No error.
# Customer is charged. Warehouse can't ship.
$ curl POST /orders
{"status": "confirmed", "total": 4995.00}
# Looks fine. Bug ships to production.
Resilient — catches it
rz main.rz
// AI wrote the same bug
let updated = decrement_stock(laptop, 5);
Error: Contract violation in fn decrement_stock:
  requires qty <= p.stock failed
blame: `decrement_stock` has `requires` on
  [p, qty]; root caller(s): [main]
// Bug caught. Code never runs.

The workflow

How vibe coding works with Resilient

The loop is simple: write contracts once, then let the AI generate implementations. The compiler tells you if the AI got it wrong.

1

Write the contract (you, 2 minutes)

Define requires and ensures for your business rules. This is the specification — what must be true, not how to implement it.

2

Vibe code the implementation (AI, 30 seconds)

Tell your AI assistant to implement the function body. It writes the code fast. Maybe it's correct, maybe not.

3

Compile (compiler + Z3, instant)

The Z3 SMT solver checks every contract at compile time. If the AI broke an invariant, you get a precise diagnostic with blame chains pointing to the exact failure.

4

Ship with confidence

Green build = proven correct. The contracts aren't tests that might miss edge cases — they're mathematical proofs that cover every possible input. live blocks handle the rest at runtime.

Why it matters

Built for the AI-assisted future

🧮

Contracts as specification

Write requires/ensures once. The AI implements, the SMT solver verifies. Humans define what, machines figure out how.

🛡️

Resilience scores

Every function gets a 0–100 resilience grade. The compiler literally tells you "this function is vibe-coded and unverified" — then tells you how to fix it.

🔄

Self-healing live blocks

live { } blocks catch transient faults, roll back state, and retry with exponential backoff. Built into the language, not a library.

🔍

Blame chains

When a contract fails, the compiler traces the violation from the failing function back to the root caller. No guessing which function caused the bug.

🎯

Typed failure modes

Functions declare fails Timeout, OutOfStock — callers must handle every failure variant. Unhandled errors are compile-time errors, not runtime surprises.

💡

Contract inference

The compiler suggests contracts for unverified functions. Start vibe-coding, then harden iteratively — the compiler guides you.
